# Codex Quota Dock

macOS 原生 Codex 额度监视器：可拖动悬浮面板、Dock 百分比、每 30 秒刷新、额度恢复至 100% 的系统通知。

## 运行

需要 macOS 13 或更新版本，且本机 Codex 已使用 ChatGPT 账号登录。

```sh
bash scripts/build.sh
open "dist/Codex Quota Dock.app"
```

首次启动会申请通知权限。允许后可点“测试通知”验证。Dock 图标右键 → 选项 → 在程序坞中保留，可固定入口。关闭窗口继续监听；菜单或 Command-Q 退出。

如需开机启动，建议将构建出的 `.app` 拖入“应用程序”，从新位置打开，然后开启“登录 Mac 时启动”。该设置默认关闭。

## 悬浮面板（0.2.0）

启动后在屏幕右下角、Dock 上方显示紧凑面板。可以拖动进度条、倒计时或面板空白处移动；位置会记住。面板切换到其他应用时保持可见，不抢占键盘焦点。

- 胶囊进度条内显示剩余百分比，下方显示 `04:25:54` 或 `6d 13:25:36` 格式的重置倒计时，每秒更新。
- 右侧调节按钮打开详情与设置；Command-逗号也可打开。
- 按实际接口结果显示一列或两列，优先显示 Codex 的短周期、长周期窗口。没有第二个窗口时不补造数值。
- 网络失败时进度条变橙，右侧显示警告；保留上次读数，详情中显示具体错误。
- 面板是独立的原生悬浮窗口，不是嵌入系统 Dock 的插件。原有 Dock 图标百分比继续保留。
- 关闭详情窗口不关闭悬浮面板；Command-Q 退出应用。

## 工作方式

- 持有一个 `codex app-server --listen stdio://` 子进程，通过 JSON-RPC 读取 `account/read` 和 `account/rateLimits/read`。不创建对话、不发起模型任务。
- 登录凭据由 Codex 自己管理；应用不读取或保存 token。优先发现已安装桌面应用内的 CLI，其次查找 PATH、Homebrew 等位置。可用 `CODEX_QUOTA_CLI` 环境变量覆盖。
- 以服务端实际返回的周期显示额度；支持多个额度桶和 primary/secondary 窗口。默认 Dock 显示 Codex 桶中剩余最少的窗口，可以在界面切换。
- 通知严格按同一账号、同一窗口的 `usedPercent > 0 → usedPercent == 0` 判定。启动即满额不通知；恢复后重复刷新不通知。保存最近观测值，跨重启去重。存储的是账号标识的 SHA-256 摘要及各窗口用量，不存储邮箱原文。
- 显示百分比向下取整，99.9% 显示 99%，不会把四舍五入的 100% 当作真正恢复。
- 30 秒正常刷新；连接失败后按 30、60、120、240、300 秒退避。失败保留旧值，Dock 加 `!`，窗口标记过期。唤醒后立即刷新；睡眠期间不监测。
- 仅监测与通知，不会自动使用额度重置券。

## 验证

```sh
bash scripts/test.sh
"dist/Codex Quota Dock.app/Contents/MacOS/CodexQuotaDock" --probe
```

`--probe` 使用与应用相同的 Swift 连接代码，只输出登录复用是否成功及各窗口剩余百分比，不输出账号或凭据。自包含测试覆盖解析、空值、首次满额、恢复去重、跨重启、账号切换、不同窗口和部分恢复；仅需 Command Line Tools，不依赖完整 Xcode 或 XCTest。

人工验收：启动后检查悬浮面板、拖动定位和设置按钮；检查 Dock 角标；等候 30 秒确认“最近更新”改变；允许通知并点“测试通知”；关闭窗口后从 Dock 重开；断网时检查过期提示；退出时确认应用的 app-server 子进程结束。

## 限制

- 这是本地构建，采用 ad-hoc 签名，未做 Developer ID 签名或公证；适用于本机自用。
- 使用安装在本机的 Codex CLI，协议或登录方式升级可能需要适配。当前读取方式参考 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。
- 定时器受系统调度与网络延迟影响，不承诺精确的 30 秒时限。专注模式及系统通知设置可能影响横幅显示。
- 重置后若额度在下次轮询前已被使用，可能观察不到 100%，不会发出“恢复至 100%”通知。
- 显示旧值时不会将网络错误或缺失字段当作额度恢复；倒计时归零本身也不会触发恢复通知。

项目不依赖第三方 Swift 包，使用 SwiftUI、AppKit、UserNotifications、ServiceManagement 和 Foundation。
